# MSG91 SMS hook for Supabase Auth

This Edge Function delivers the OTP generated by Supabase Auth through an approved MSG91 SMS Flow. The browser continues to use `signInWithOtp` and `verifyOtp`; MSG91 does not verify or generate a separate code.

## MSG91 setup

1. Complete the India DLT entity, sender/header, and content-template registration.
2. In MSG91, create an SMS Flow/template whose approved message contains the variable `##OTP##`.
3. Map the approved DLT template to that MSG91 template.
4. Create an MSG91 auth key restricted to the SMS/Flow API where possible.

## Required Supabase Edge Function secrets

- `MSG91_AUTH_KEY`: the restricted MSG91 auth key.
- `MSG91_TEMPLATE_ID`: the MSG91 SMS Flow/template ID.
- `MSG91_OTP_VARIABLE`: optional; defaults to `OTP` and must exactly match the MSG91 variable name.
- `SEND_SMS_HOOK_SECRET`: the Standard Webhooks signing secret used by the Supabase Send SMS Hook, including its `v1,whsec_` prefix.

Never put these values in the repository or in frontend/Vercel environment variables.

## Deploy and activate

1. Deploy `send-sms-msg91` with JWT verification disabled. The function authenticates requests using the Supabase Auth Hook signature instead of a user JWT:

   ```sh
   supabase functions deploy send-sms-msg91 --no-verify-jwt
   ```

2. In the Supabase dashboard, open **Authentication → Hooks → Send SMS Hook** and choose an HTTPS hook.
3. Use this function URL:

   ```text
   https://<project-ref>.supabase.co/functions/v1/send-sms-msg91
   ```

4. Use the same generated hook secret as `SEND_SMS_HOOK_SECRET` in the Edge Function secrets.
5. Ensure Phone authentication is enabled. Keep the existing 60-second OTP request limit, and enable CAPTCHA before wider public use.
6. Test with an existing customer phone number because the application currently calls `signInWithOtp` with `shouldCreateUser: false`.

The hook intentionally accepts only Indian mobile numbers and never logs the phone number or OTP.
